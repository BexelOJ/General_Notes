The learning progression

The important thing is not to memorize 290 APIs. 
The projects build the architecture progressively:

Processes
   ↓
fork / exec / wait
   ↓
Pipes
   ↓
FIFO
   ↓
Signals
   ↓
Message Queues
   ↓
Shared Memory
   ↓
Synchronization
   ↓
UNIX Domain Sockets
   ↓
TCP / UDP
   ↓
select / poll / epoll
   ↓
eventfd / timerfd / signalfd
   ↓
File Descriptor Passing
   ↓
Zero-Copy / Ring Buffers
   ↓
Kernel IPC
   ↓
Device Driver ↔ User Space
   ↓
Qt ↔ Backend
   ↓
RPC / gRPC / MQTT
   ↓
Containers / Namespaces
   ↓
Production IPC Architecture

-----------------------------------------------------
How this fits your other learning tracks

You now have three very useful parallel tracks:


                    Linux
                      │
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
     FreeRTOS       IPC       Device Drivers
        │             │             │
        ↓             ↓             ↓
     Embedded      Linux Apps     Kernel
        │             │             │
        └─────────────┼─────────────┘
                      ↓
                 Embedded Linux
                      │
                      ↓
              Qt / Applications
                      │
                      ↓
              Real Products
			  
			  
For your learning path, I would make IPC primarily 
Linux/POSIX-based, because it will connect directly 
to your upcoming Linux kernel, device-driver, Qt, 
Raspberry Pi, and server work.
