The useful FreeRTOS prefix pattern

You'll see these prefixes everywhere in FreeRTOS:

Prefix		Meaning		Example

  p			pointer		pSomething

  c			char		cName 
  x			FreeRTOS base/type conventionxTaskHandle

  v			void		pvParameters

  s			short		sValue
  l			long		lValue
  f			float		fValue
  d			double		dValue
  u			unsigned	uValue

-----------------------------------------------------

pcName          → pointer to char/string
usStackDepth    → unsigned stack depth

pvParameters    → pointer to void
uxPriority      → unsigned priority value
pvCreatedTask   → pointer to TaskHandle_t

xCoreID         → core ID value

In FreeRTOS, Inter-Task Communication (ITC) means 
mechanisms that allow one task 
to send data/signals to another task safely.

The main mechanisms are:

Mechanism - Purpose	- Data transfer - Typical use:

Queue - Send data between tasks - 
✅ Yes - Sensor → processing task

Binary Semaphore - Signal/event synchronization
❌ Usually no data - Task → task notification

Counting Semaphore - 
Count available resources/events - 
❌ Usually no data - Resource pool/event counting

Mutex - Protect shared resource - 
❌ No - Shared I²C/UART/SPI

Recursive Mutex - 
Mutex that same task can lock repeatedly - 
❌ No - Nested resource access

Task Notification - 
Very lightweight task-to-task communication - 	
✅ Small value/notification - Fast signaling

Event Groups - 
Communicate multiple event conditions - 
✅ Bit flags - "Wi-Fi + sensor + config ready"

Stream Buffer - Transfer byte streams - 	
✅ Bytes - UART-like data

Message Buffer - 
Transfer variable-size messages - 
✅ Messages - Protocol packets
