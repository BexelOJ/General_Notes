Phase 1 — Yocto "Hello World"
-----------------------------------------------------
Goal: Build your first Yocto image without 
modifying anything.

Learn:

Yocto
 └── OpenEmbedded
      └── BitBake

Understand:

Poky
BitBake
metadata
recipes
layers
configuration
image
machine
distro

First project:

yocto_01_minimal

Build:

core-image-minimal

Understand:

conf/local.conf
conf/bblayers.conf

and:

bitbake core-image-minimal
Result

You can build a bootable minimal Linux image.

-----------------------------------------------------
Phase 2 — Understand the Build System
-----------------------------------------------------
Goal: Stop treating Yocto as a black box.

Study:

build/
├── conf/
│   ├── local.conf
│   └── bblayers.conf
│
├── tmp/
├── sstate-cache/
└── downloads/

Understand:

BitBake
   ↓
Recipe
   ↓
Task
   ↓
Source
   ↓
Compile
   ↓
Package
   ↓
Root filesystem
   ↓
Image

Important tasks:

do_fetch
do_unpack
do_patch
do_configure
do_compile
do_install
do_package
do_rootfs
do_image

Practice:

bitbake -c fetch <recipe>
bitbake -c compile <recipe>
bitbake -c install <recipe>
bitbake -c clean <recipe>

Phase 7 — Custom Image
-----------------------------------------------------
Create your own image recipe:

meta-exin/
└── recipes-core/
    └── images/
        └── exin-image.bb

Instead of:

core-image-minimal

you now have:

exin-image

Example:

exin-image
├── BusyBox
├── systemd
├── SSH
├── your application
├── your service
└── configuration

This becomes your first real embedded 
Linux distribution image.

I would make the first Yocto milestone 
extremely small: 
build core-image-minimal, 
boot it in QEMU first, 
understand the generated files, 

then build the same progression 
for your Raspberry Pi. 

That gives you a clean minimum → application → 
kernel → driver → BSP → production 
path rather than jumping directly into a 
complicated Yocto setup.
